八条规则

每条规则都对应一个真实犯过的错误。

HypGraph 源自一个做长期研究的 AI 智能体团队，以及它们在被明确告知不要犯的情况下仍然犯下的错误。每个错误都变成了一条规则，由记录在写入工作时强制执行，而不是一条只能期望被遵守的建议。

现状是推导出来的

没有任何字段写着“已确认”。审查、风险、支撑和证据强度都在读取时由记录计算得出。

只追加

用 SHA-256 串成链。更正是新版本；撤回的内容仍留在记录中。verify() 能发现任何编辑。

审查固定版本

修正一条已核查的主张，其核查就会过时。基于旧版本的决策会被标记为需要重审。

主张带着数字

主张中的数字绑定到结果字段。没有来源的数字会被拒绝 — 这是摘要出错最常见的方式。

独立性被计数

同一次运行得出的三个结果是一条证据线，而不是三条。共享数据或来源的证据线会合并。

排除需要检验力

只有在证明某次搜索能找到预埋的答案之后，才能说“排除”。否则结果是不确定的。

作者不审查自己

只有指定审查者的裁定才算数，而且不能针对自己的工作。其他人的裁定保留为评论。

仪器自己说话

只有实验室执行器才能记录一次实验室运行。你描述的运行会被标记为你的报告。

从不的算术

次测试中出现 次失败，在一百万次使用中仍可能有 次。

一个在测试中一次也没看到的智能体会写下“从不发生”。记录拒绝这句话并要求给出计数，然后说明在你部署的规模下这些计数还留有多少余地。

一步一步的算术

在 次使用中未被排除的失败，置信度 95%，依据 次测试中的 次。

一份记录，五种工作流

每个学科的方法，由记录来执行。

一种配置包含其学科的各个阶段、每个阶段的出口关卡，以及什么算完成。阶段由记录推导，从不由智能体设定。每一行都有一个在线示例。

信任

记录展示了什么，又不主张什么。

✓ 它展示

  • 没有任何事件在写入后被改动：每次写入都被哈希进一条任何人都可以重新检查的链；
  • 主张中的哪些数字绑定到哪个结果，以及是哪次运行产生了它；
  • 谁针对哪个版本核查了什么，以及该版本是否仍然有效；
  • 如果某个前提被撤回，什么会随之倒下。

— 它不主张

  • 某条主张为真。它检查写下的内容与记录的内容是否一致；
  • 让模型推理得更好。它把模型的过度主张挡在记录之外；
  • 任何关于随记录包附带的遥测的内容：遥测在哈希链之外；
  • 检查限定范围的记录包所隐藏的事件。验证会指出记录包何时限定了范围。

它在你运行它的地方运行：一个本地文件，无需账户，自身不发起网络调用。版本通过可信发布从 GitHub Actions 发布到 PyPI。
