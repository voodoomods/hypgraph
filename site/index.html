A record that checks what your agents claim.

Agents write their hypotheses, runs, results and claims into HypGraph. It refuses a number no result accounts for, “always” without the counts and “ruled out” without a powered search, and works out from the record on every read what has been shown and what is at risk.

What it refuses

Overclaims don't get into the record.

These were written into a scratch record when this page was built. The engine refused each one with a code and what to fix; the rewrite underneath, on the same evidence, was accepted.

Eight rules

Each rule is a mistake that was really made.

HypGraph came out of a team of AI agents doing long investigations, and the errors they made despite instructions not to. Each became a rule the record enforces when work is written, not advice it hopes is followed.

Standing is derived

No field says “confirmed”. Review, risk, support and evidence strength are computed from the record when it is read.

Append-only

Hash-chained with SHA-256. Corrections are new versions; withdrawals stay on record. verify() catches an edit.

Reviews pin versions

Revise a checked claim and its check goes stale. A decision based on the old version is flagged to revisit.

Claims carry numbers

A claim's numbers are bound to result fields. A number with no source is refused — the commonest way summaries go wrong.

Independence is counted

Three results from one run are one line of evidence, not three. Lines that share data or a source merge.

Exclusions need power

“Rules out” only after a search was shown to find a planted answer. Otherwise it's inconclusive.

Authors don't review themselves

Only named reviewers' verdicts count, and not on their own work. Others' are kept as comments.

Instruments speak for themselves

Only the lab runner files a lab-recorded run. A run you describe is labelled as your report.

The arithmetic of never

failures in tests still leaves across a million uses.

An agent that sees none in its tests writes “it never happens”. The record refuses that sentence and asks for the counts, then states what they leave open at the scale you deploy.

Trust

What the record shows, and what it doesn't claim.

✓ It shows

  • that no event was changed after it was written: each write is hashed into a chain, and anyone can re-check it;
  • which numbers in a claim are bound to which result, and which run produced it;
  • who checked what, against which version, and whether that version is still current;
  • what falls if a premise is withdrawn.

— It doesn't claim

  • that a claim is true. It checks what was written against what was recorded;
  • to make a model reason better. It keeps a model's overclaims out of the record;
  • anything about telemetry carried in a bundle: that sits outside the hash chain;
  • to check events a scoped bundle redacts. Verification says when a bundle is scoped.

It runs where you run it: a local file, no account, and no network calls of its own. Releases are published to PyPI from GitHub Actions by trusted publishing.
