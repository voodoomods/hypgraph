The record format

Everything needed to write another implementation, a verifier or a viewer of HypGraph records.

1. Model2. Vocabulary3. Canonical JSON and the event chain4. Bundles — hypgraph/1-bundle5. Derived standing (normative)6. Write rules (normative for writers)7. Claim checks8. The refusal log9. Checking a write-up against the record

Status: draft 3 (HypGraph 0.3). Licence: CC BY 4.0. This page is enough to write another implementation, a verifier or a viewer.

1. Model

A record is a set of nodes (typed, versioned), edges (typed links between two nodes), withdrawals, retractions (of edges), leases (who is working on a node) and events. Every table is append-only: a correction is a new row, never an edited one.

  • A node has an id, a type, a display code (H1, CL3 …, unique per type within its investigation), the

investigation it belongs to (inv, empty for an investigation itself), created_at and created_by.

  • Its content lives in versions (node, v, at, by, reason, body). body is the canonical JSON (§3) of the

node's fields. The current version is the highest v.

  • An edge records the version of each end when it was made (src_v, dst_v). A review or decision is about that

version.

3. Canonical JSON and the event chain

canon(x) is JSON with keys sorted at every level, separators , and : with no spaces, and non-ASCII characters written as-is (UTF-8). In Python: json.dumps(x, sort_keys=True, ensure_ascii=False, separators=(",", ":")).

Every write appends one or more events. An event's hash is

hash = sha256_hex( canon({"at", "actor", "kind", "ref", "payload", "prev"}) )

where prev is the previous event's hash (64 zeros for the first). Kinds and payloads:

kindrefpayload
createthe new node{type, code, inv, v: 1, body_sha}; body_sha = sha256 of the version's stored body string
revisethe node{v, reason, body_sha}
reviewthe reviewed node{review: <review node id>, verdict, on_v, official, body_sha}
linkthe edge's source{edge, rel, dst, src_v, dst_v, data_sha}; data_sha = sha256 of the stored edge data string
retractthe edge's source{edge}
withdrawthe node{why}
lease_take / lease_releasethe node{task, expires}

Any event may carry task in its payload: the unit of work that wrote it.

Verifying a record means recomputing every hash in order and checking each prev. Then check that every stored version body and edge matches the body_sha / data_sha of the event that wrote it, and that no row exists without its event.

4. Bundles — hypgraph/1-bundle

A portable record. Every event is carried as the exact string that was hashed (body), and every version body and edge data as the exact stored string. A verifier therefore never has to reproduce canonical JSON: it hashes strings and compares.

{"format": "hypgraph/1-bundle", "generator": "hypgraph 0.1.0", "exported_at": "…",
 "complete": true, "redacted_events": 0, "scope": {"inv": "", "title": "whole graph"},
 "policy": {"reviewers": [], "instrument": "lab", "operator": "operator", "importer": "importer", "system": "system"},
 "head": "<hash of the last event>",
 "events": [{"seq": 1, "hash": "…", "body": "{\"actor\":…,\"at\":…,\"kind\":…,\"payload\":{…},\"prev\":…,\"ref\":…}"}],
 "nodes": [{"id": "…", "type": "…", "code": "…", "inv": "…", "created_at": "…", "created_by": "…"}],
 "versions": [{"node": "…", "v": 1, "at": "…", "by": "…", "reason": "", "body": "<stored canonical string>"}],
 "edges": [{"id": 1, "src": "…", "src_v": 1, "rel": "…", "dst": "…", "dst_v": 1, "data": "<stored string>", "…": "…"}],
 "withdrawals": [], "retractions": [], "leases": [],
 "derived": {"…": "standing at export time, for viewers; never trusted by a verifier"}}

A scoped bundle (one investigation out of a shared record) replaces events outside it with {"seq", "hash", "prev", "redacted": true}. The chain still links, but the content of those events can't be checked, so a change hidden among them would not show. Verifiers must report complete: false. To publish a study, keep it in a record of its own.

Anchoring. A bundle proves only its own consistency. To prove it wasn't rebuilt from scratch, publish its head hash somewhere independent at the time (a paper, a preregistration, a repository tag). A later bundle whose chain passes through that hash can't have rewritten anything before it.

5. Derived standing (normative)

Implementations must derive these, never store them:

  • lifecycle: withdrawn if withdrawn; superseded if a live node of the same type supersedes / corrects

it; an investigation's own state; else active.

  • review: computed over reviews by the board (the policy's reviewers ∪ the investigation's reviewers ∪ the

operator and importer), excluding comments. An objection stays open until its author records resolved. The operator, the importer and the investigation's reviewers may resolve anyone's. Then, on the current version: any negative verdict or open objection → contested; else any positive verdict → checked; else a positive verdict only on an older version → needs_revalidation; else unchecked.

  • fallen: withdrawn; or a contested claim / result / hypothesis; or a run whose state is failed / timeout /

cancelled / interrupted; or a result whose outcome is failed. Superseded is not fallen.

  • at_risk: the fallen nodes reachable upstream through requires, derived_from, based_on and the run that

produced it.

  • independent lines: live supporters, grouped when their roots overlap. Roots are producing runs, the data /

model artifacts those runs use, and sources. Supporters with no provenance at all form one group between them.

  • evidence: the best live supporter's profile, ranked `unverified < agent_reported < lab_recorded <

project_rerun < separate_implementation < new_data < external`.

    • A source is external.
    • A result produced by a kind=lab run that the instrument filed is lab_recorded.
    • A replication edge on the run raises the profile according to its differs.
    • A result of kind=cited is external only if it cites a source node.
  • basis_changed (decisions): a based_on edge whose target's version has moved past the pinned dst_v.

6. Write rules (normative for writers)

  • supports / challenges need a why of at least 10 characters. tests needs data.expected. replicates

needs data.differs. uses needs data.role.

  • Only the instrument files a kind=lab run, and only the instrument records what that run produced.
  • Claims must pass the checks in §7, unless written by the operator or importer, or in an investigation with

strict_claims: false.

  • Nobody officially reviews their own node.
  • Writes into an archived or published investigation are refused (reserved authors excepted).
  • Only the importer may set a write's time. Everyone else's comes from the writer's clock.

7. Claim checks

A claim is checked before it enters the record. Each failed rule is reported with a stable code, a message that does the arithmetic, a suggested fix, and the words that triggered it. Checks are skipped for the operator and importer, and in an investigation with strict_claims: false. Leads and conventions skip rules 7–9.

Arithmetic. For a count of k in n trials, the 95% interval is the Wilson score interval. At k = 0 (or k = n) it is the exact one-sided bound 1 − 0.05^(1/n), the "rule of three" (≈ 3/n). "Never, in n trials" means at most that rate, and never zero. Two counts are compared with Newcombe's hybrid score interval and a pooled two-proportion z-test. The smallest detectable difference uses 80% power at two-sided α = 0.05.

With two counts, the message gives the smallest detectable difference.
11UNCORRECTED_EFFECTa finding asserts an effect (changes, lowers, differs, affects, significant, …) on an outcome, while a live result in the investigation holds that outcome's corrected p-value (a field named with holm / bonferroni / fdr / adjusted / corrected …) at or above 0.05, or a count of 0 outcomes surviving correction (n_holm_sig), and the effect word is neither qualified within 20 words as uncorrected (uncorrected, unadjusted, nominally, without correction, …) nor names the correction with a corrected value bound as a measurement. A family-wide value (min_adjusted_p) applies when the claim binds a nominal p < 0.05. Thresholds (bonferroni_alpha_threshold) are not evidence. Honest forms: bind the corrected p and say "not significant after correction", or file kind: lead.

Exposure. A claim may set exposure (how many uses, users or units it will be applied to) and exposure_unit. Absolute refusals then state how many failures the bound leaves unruled out at that scale. An accepted claim's standing carries bounds (per count: k, n, rate, lo, hi and, with exposure, unruled_out), its sentence reads "'never' = at most 0.1% (0 of 3,000, 95%), up to 998 of 1,000,000 not ruled out", and a "significantly" claim carries test (the difference, its interval and p).

Blast radius. Withdrawing a node, or a verdict that makes it fall, returns blast_radius: every node resting on it by type, with claims and decisions named and, if a spend meter is connected, the cost of the work behind them.

8. The refusal log

A refused claim never enters the record, so its trace lives in a separate append-only table, refusal_log, with its own SHA-256 chain over canon({at, kind, author, inv, node, op, statement, codes, detail, ref, prev}). The record's own chain and verify() are unaffected.

  • kind: refused: the author, the investigation, the statement (≤ 1,500 characters; a result's summary), the

sorted codes, and the problems (code, message, fix) it was refused with; detail holds the whole body, the support it had and the node type (claim, result, or a typed node). op is create or revise; node is set for a revision.

  • A refusal on shape — a field the type doesn't have (SHAPE_UNKNOWN_FIELD), a value outside an enum

(SHAPE_NOT_AN_OPTION), a missing, too long or too short field, a wrong type, or a link the relation grammar refuses (LINK_NOT_ALLOWED, LINK_UNKNOWN_RELATION, LINK_NO_NODE) — is logged the same way with detail.type shape or link. Its message carries the fix: where the field goes (code on a result belongs to the run; an experiment's expected goes on its tests link) or what each option means. The report counts these apart from overclaims and the replay skips them.

  • kind: fixed: a later claim, result or revision by the same author in the same investigation, accepted within

24 hours, that says the same thing. "The same" means the same node for a revision; otherwise a Jaccard overlap ≥ 0.3 of the statements' content words, or, for a result, at least half of the refused result's value keys carried again. ref is the refusal it fixes.

A report aggregates per author (refused, fixed, open, codes) and per rule. A replay runs every logged refusal through the checker as it is now — claims through the claim and profile checks, results through the value and profile result checks as their author — and says for each whether it would be refused the same way, differently, or accepted; RESULT_RESTATES and typed-node refusals depend on the record's state at the time and are counted as skipped. A change to a rule is judged on that replay over the real corpus before it ships.

9. Checking a write-up against the record

A checker reads markdown sentence by sentence and checks it against the record. Code blocks, inline code, URLs, link targets and HTML comments are skipped, except a fenced block whose info string is answers: that is the report's machine-read answer (a JSON object, keyed by question code or flat), and every number or true / false in it is checked against the claims. Quoted passages and negated words ("cannot be proven") are not treated as the writer's assertion. Codes are matched within the investigation being reported on.
